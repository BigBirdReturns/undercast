# Census adapter SDK

The adapter SDK separates a source-specific census producer from the generic UNDERCAST observation, certification, queue, and estate-control layers. An adapter contract identifies one estate, one Autopilot scope, one franchise label, the exact source hosts, the declared producer command, the producer files already held by scope certification, the output receipt fields, and the semantic controls that must survive review.

Registration is evidence only. It does not certify an adapter, activate an estate, issue a Luna lease, mutate canonical records, or complete the roadmap milestone. Those effects require separate reviewed receipts after a current source regeneration and semantic review.

## Shared output contract

Every adapter emits observations into `data/CENSUS-MANIFEST.json`. Each observation must preserve:

```text
franchise
source URL
page ID
revision ID
content SHA-256
observed timestamp
category and disposition
```

Identical source, page, revision, and content identities may appear under several source categories. The adapter baseline counts those as duplicate category facets while preserving one exact source-revision identity. Category overlap therefore cannot manufacture independent evidence.

## Reference and candidate

`star-trek-v1` is the frozen certified reference. It demonstrates the current full-canon, exact performer-role and performance-mode contract. Its existence does not force another estate to copy Star Trek source assumptions.

`doctor-who-v1` is the first review candidate because Doctor Who is the highest-priority registered estate already at adapter review. Its contract requires a fresh regeneration and explicit review of compact infobox parsing, exact actor-role joins, incarnations and recasts, voice and physical modes, suits and creatures, and archive-footage boundaries. The baseline may report that regeneration or receipt repair is required. It may not certify Doctor Who by inference.

## Commands

```text
npm run adapter:write
npm run adapter:check
npm run adapter:status
npm run adapter:fixtures
```

The write command deterministically records the current adapter baseline under `data/review/adapter-sdk/BASELINE.json`. The check command refuses stale generated bytes. The status command calculates the same object without changing the repository. The fixtures reject scope and estate rebinding, undeclared refresh commands, missing producer custody, certification authority, receipt gaps, host drift, malformed hashes, and evidence inflation through duplicate categories.

## Advancement law

```text
registered review candidate
→ current source regeneration
→ exact revision and content custody
→ adapter-specific semantic review
→ preserved snapshot
→ second-desk certification receipt
→ certified-paused estate
→ separately authorized activation
→ independently completed second gold shard
```

A configured shelf, an existing crawler mode, or old manifest rows cannot skip any step. Unknown and unavailable source evidence remain visible debt rather than absence or ineligibility.
