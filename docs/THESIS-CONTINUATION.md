# UNDERCAST thesis continuation rail

This rail exists so a completed cycle returns directly to collection instead of
spawning another bespoke selector, census, blueprint, transition, observer, or
cleanup architecture.

UNDERCAST is a field index of real performers who disappear under a designed
face, prosthetics, a mask, a creature suit, motion capture, or an unseen voice.
Every ordinary increment must improve a canonical character-to-performer reveal,
its exact source and media evidence, an honest absence, a correction, a preserved
source, or a source-backed maker credit.

## Use it after the current cycle is terminal

Run from clean canonical `main`:

```bash
node scripts/thesis-rails.mjs validate
node scripts/thesis-rails.mjs status
node scripts/thesis-rails.mjs next --json
node scripts/thesis-rails.mjs prompt --out .luna/THESIS-CONTINUATION.md
```

Give the generated prompt to the next worker. It contains the machine-selected
phase, estate, scope, exact first compatible candidate when a claim is lawful,
and the command that creates the one-task Autopilot lease.

The rail is read-only. It does not claim a task, mutate a queue, adopt media,
write a receipt, update a ref, or publish a card.

## Phase order

The rail derives one phase from canonical state:

```text
finish-current-cycle
→ close-media-debt
→ inspect-waterline or inspect-capability
→ ready-for-one-cycle
→ advance-estate-gate
→ collection-complete
```

A higher-priority active estate controls the next operation. The rail does not
skip a blocked active estate to free-select a more interesting franchise.

A new cycle is available only when all active-cycle custody is terminal:

```text
in flight             0
media debt            0
unreceipted cycles    0
claimable waterline   true
compatible candidate  present
batch limit           1
```

Open noncanonical pull requests and branches are not canonical corpus state. The
worker must still prove the prior cycle's exact temporary namespace is empty
before executing the printed lease command.

## Normal cycle topology

The normal implementation surface is limited to:

1. one candidate or product lane;
2. one independent exact-product review; and
3. one receipt-bearing finalizer that publishes the canonical card, writes the
   waterline receipt, proves the terminal queue and media state, and removes all
   temporary surfaces.

An exact shared-mechanism defect may be repaired in that lane. It does not justify
a new selector, preflight, evidence census, modality desk, blueprint, candidate
transition controller, review transition controller, finalizer census, observer,
or cleanup-writer series.

A performer portrait remains performer evidence. A character still remains
character evidence. Neither may substitute for the other. Missing exact media is
recorded as honest absence. Maker attribution is valuable but nonblocking: add it
only from exact source support and leave it explicitly unresolved otherwise.

## Pull-request rail

Cycle 012 is explicitly grandfathered so the rail can be merged without disrupting the active Senstarg transaction. Workflow-topology enforcement begins with cycle 013.

The collection policy runs:

```bash
node scripts/thesis-rails.mjs check-pr --base "$BASE_SHA" --event "$GITHUB_EVENT_PATH" --json
```

A cycle workflow pull request must declare:

```text
Terminal-Product: <exact canonical card, correction, media closure, refresh, or gate>
```

A normal cycle may change at most three cycle-specific workflow files. The
transition-only stage names listed in `data/THESIS-RAILS.json` fail closed. A real
shared-mechanism exception must carry all three receipts in the pull-request body:

```text
Thesis-Rail-Exception: <why the normal lane cannot complete>
Shared-Mechanism-Gap: <the exact reusable defect>
Retirement-Condition: <how the exception disappears in the terminal product>
```

The exception is not a license to widen the cycle. It is a bounded repair ledger.

## Terminal definition

A successful cycle ends only when the canonical repository shows:

```text
one exact task resolved
one reviewed cycle receipt
zero in-flight tasks
zero media debt
zero unreceipted cycles
zero temporary cycle refs
permanent routes and projections rebuilt
the complete repository gate passed
```

The next claim begins only after that state is visible on canonical `main`.
