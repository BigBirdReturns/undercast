## Composite-gate future safety

The preceding pilot checker no longer reads mutable live ledgers. It resolves the complete first-pilot world from immutable commit `04551b140022c7b733b0290e10c7e40905aabc76`, requires every commit/path result to exist as a Git blob, and then replays the original cycle, lease, source, queue, wall, media, and receipt assertions against those historical bytes. Later tasks, source refreshes, or exact media therefore cannot make the first-pilot proof fail.

The preceding activation checker now applies the same boundary. The activation-era task is recovered from `79362e21d9d526f1310467574e69fe909eb80adb:data/AUTOPILOT.json`, Git blob `178e51eecfddf759b97fcaf29741df7736e68a70`; the global-cycle code hashes are recomputed from exact reviewed bytes at permanent main commit `9e5f39d22df254136fdc4a7b34d93ebd17bf1172`. Current live task identity must remain Commander/Dan Starkey in Doctor Who, but later certified source URLs and fingerprints may advance without reopening the activation transaction.

A certified refresh is not a free-form URL change. The normalized current task URL set must exactly equal the URL set represented by current source receipts, every receipt must retain positive page and revision identity plus a content hash, and `source_fingerprint` must recompute through the canonical Autopilot source model. Embedded fixtures accept a fully receipted refresh and reject both stale receipts and a forged fingerprint.

This law is applied to every non-rejected, non-retired Doctor Who task, not only Commander and Slite. The activation checker and correction checker each iterate the complete live scope. An adversarial Mezz mutation changes its task URL, retains the old receipt, recomputes the canonical fingerprint over that inconsistent state, and is still rejected because the normalized task and receipt URL sets disagree.

Every current task source and source-receipt source must also parse as an HTTPS URL with a hostname and no embedded credentials before canonical-key comparison. Matching malformed tokens therefore do not become valid merely because the task and receipt repeat the same text, and matching HTTP URLs are refused. Embedded Mezz fixtures pay both boundaries.

Doctor Who membership is derived from the canonical normalized franchise identity, and every task’s mutable scope must agree with that identity before the live denominator is selected. A task therefore cannot escape provenance checks by changing `scope` to another estate. Cross-task receipt separation also uses the canonical `sourceKey` rather than the raw URL spelling, so trailing slashes and other equivalent URL forms cannot make Commander and Slite appear independently sourced when they share the same page, revision, and content hash.

Lawful retirement and certified-refresh adversarial proofs are separate worlds. The real Commander task may be `retired` and exit live source custody, while the refresh, stale-receipt, and forged-fingerprint fixtures are explicitly normalized to a non-retired `resolved` status before source validation. Retirement therefore cannot short-circuit the negative refresh proofs, and the negative refresh proofs cannot make retirement illegal.

Presence is also part of custody. Both permanent checkers rebuild the authoritative current task set with canonical `collapseCoverage(data/CENSUS-COVERAGE.json, data/AUTOPILOT-SCOPES.json, data/CENSUS-MANIFEST.json)` and require those Doctor Who task IDs to equal the non-retired Doctor Who jobs in `data/AUTOPILOT.json`. Removing Mezz while leaving the remaining state internally valid therefore fails closed as a missing current canonical obligation.

Canonical sync does not delete an obligation merely because it leaves current coverage. It retains the exact job as `retired`, removes any lease, records `outcome.kind = not-in-latest-coverage` with `retired_at`, and appends a matching `task.retired` journal event. The checkers validate that retained retired jobs separately: they must be absent from current coverage, carry the canonical sync outcome, have no lease, and match exactly one retirement event by task, scope, performer, role, and timestamp. A covered retired task, an unreceipted retirement, or a deleted current task fails closed.
